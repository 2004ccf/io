Skill 学习与专业能力 通用冷知识

使用 AI 的工具集合

Prompt、Agent、Skill、MCP、IDE、Claude Code 等概念对照与组合用法，用「开公司」比喻一次搞懂。

Jun 30, 2026

我为什么写这篇

2026 年初我开始用 Cursor 写代码、整理笔记，界面里同时出现 Prompt、Agent、Skill、MCP 这些词，和网页版 ChatGPT 的「对话框」完全不是一回事。我查了很多教程，有的只讲 Prompt 技巧，有的直接跳到 Agent，看完仍然对不上号——不知道哪个管「怎么说」，哪个管「自己干」，哪个管「接 GitHub」。

后来我把笔记里的「开公司」比喻反复读了几遍，又对照 Cursor 里的实际功能试了一遍，才慢慢理顺。这篇是我按自己的理解整理的，方便以后给领导展示学习成果时，也能说清我在用什么、为什么这么用。

用「开公司」对照：人、规章、工具、权限

我把 GPT、Claude、DeepSeek、Gemini 这类大模型想成刚入职的高能力员工：脑子快，读文档、写代码都行，但不了解我平时的写法、项目结构和习惯。

Prompt 是我站在工位旁口头交代：「参考上次 A 客户的版本写方案，语言精简。」说完就结束，不会自动写进制度，明天再开一个新对话，它也不记得今天这句。

Agent 是我只给目标：「做一份竞品分析。」它自己拆步骤、搜资料、调工具、改稿、检查。我不用每一步都下指令。

Skill 是我提前写好的 SOP：标准步骤、模板、参考案例、注意事项。Agent 干活时翻这份手册，而不是每次靠我临场口述。输出会稳很多，也更像我自己的风格。

MCP（Model Context Protocol，模型上下文协议）像统一的门禁卡。GitHub、Notion、搜索引擎、Slack 等外部系统，用同一套协议接进来，AI 才能安全、规范地去拿真实数据。Skill 解决「怎么干」，MCP 解决「数据从哪来」——一个是方法论，一个是权限和接口。

IDE（Cursor、Trae、Windsurf 等）是带 AI 的办公室：编辑器里就有补全、Agent、Skill 配置、MCP 插件，我日常写代码基本都在这里。

Claude Code / OpenCode 更像终端里的专项人员：不依赖图形界面，直接在命令行读写仓库、跑脚本。Claude Code 绑 Claude 系列；OpenCode 开源，可多模型切换。适合「就地在仓库里硬改」的批量任务。

压成一句：LLM 是能力底座；Prompt 是一次性交代；Skill 是可复用的干法；Agent 是自主执行；MCP 是接外部系统；IDE / 终端只是工作地点不同。

Prompt 在 2026 年：没消失，只是退到幕后

网上常说「Prompt 已死」，我的体会是：手工写很长 Prompt 的需求在减少，但 Prompt 并没有退场。Agent 每一步行动背后仍在生成 Prompt；Skill 本质上也是一组设计好的 Prompt 片段加流程。重点从「雕句式」转向「设计 Skill 和流程」，让系统在合适节点自动生成对的指令。

当大模型能力、Agent 自主性、Skill 方法论、MCP 接入这四块配在一起时，有些原本要两三天的整理或选型，可能压到几十分钟——前提是我会搭组合，而不是只会单次问答。真正的红利，在我看来，不是多背几个模型参数，而是会用这些组件重新设计写文档、改代码、做分析的方式。

我整理过程中搞清的几个问题

这些概念到底怎么分？实战怎么配？

我现在的用法是：日常开发在 Cursor 里，把它当办公室；配好写文档、重构代码的 Skill，用 MCP 接 GitHub 和搜索；开 Agent 模式时给目标让它自己跑。需要大批量改仓库、脚本驱动时，再开 Claude Code 或 OpenCode 在终端处理。两者可以配合，不必二选一——我在 Cursor 里看清结构、小步修改，在终端里做跨目录的大改，这样分工比较顺。

Agent 自带 Skill 和我自己写的有什么区别？

Agent 自带的是通用能力：写代码、总结、翻译、简单分析，不针对我的业务和文风。我写的 Skill 是「本公司手册」——固定步骤、输出格式、用词习惯、案例。没有自定义 Skill 时也能用，但结果时好时坏；加载我的 Skill 后，Agent 会优先按 SOP 走，可控性明显提高。

我打算把最常做的三类活——写技术报告、整理访谈、做选型比较——分别写成独立 Skill，标题结构、列点习惯也固定下来，让不同工具里的 Agent 尽量按同一套标准输出。

Claude Code 是不是「操作系统助手」？Cursor 算哪一类？

都不是操作系统层。Claude Code、OpenCode 是终端里的开发助手，跑在 Windows / macOS / Linux 之上；Cursor 是 AI IDE，和 VS Code、JetBrains 同一层。我记楼层：最底是 OS，中间是终端、IDE、浏览器，Claude Code 偏终端特种兵，Cursor 偏图形办公室。

写 Skill 时我也在考虑：同一套 SOP 是否分别写「Cursor 版」和「终端版」，因为有的任务适合可视化翻项目树，有的适合脚本批量处理。

AI、大模型、LLM 怎么套？

AI 范围最大；大模型是 AI 里用海量数据训练出来的子集，不限语言；LLM（大语言模型）专指处理自然语言的那一类，如 GPT、Claude 的语言部分。集合关系：LLM ⊂ 大模型 ⊂ AI。日常说「用大模型」，多数时候就是在用 LLM。

除了 MCP 和 Skill，还有哪些给 AI 加功能的路子？

我按 2026 年能查到的资料，归纳了六条主线（很多产品是组合使用）：

1. 检索增强生成（RAG）
让模型回答前先检索外部知识库，再生成答案，解决「模型不知道我本地私有资料」的问题。企业知识库问答、本地化 AI 库常用「向量库 + RAG」。

2. 工具调用 / 函数调用（Tool Use / Function Calling）
让 LLM 在推理中主动调 API、数据库、代码解释器。代表思路包括 Toolformer、ReAct、PAL 等；GPT、Claude 的 tools 能力都在这条线上，MCP 则进一步统一工具生态的协议。

3. 多步骤推理与规划（CoT / ToT / ReAct 式 Agent）
把复杂任务拆成多步，逐步规划与验证。Cursor Agent、各类 Coding Agent 背后广泛用到这类思路。

4. 多智能体（Multi-Agent）
多个不同角色的 Agent 协作，如写代码 + 测试 + 文档。框架有 AutoGen、Swarm 等。

5. 工作流编排（Workflow / Agent Graph）
用流程图、状态机把 Agent 和工具串成可复用流水线。LangGraph、Coze 工作流等属于这一类。

6. 知识结构增强（GraphRAG / Markdown 知识图谱）
用图谱或 Markdown 双链让 Agent 沿结构检索，而不是乱翻长文档。我自己的 Obsidian 笔记库，其实已经在往这个方向靠——主题划分 + 问答区，再接 RAG 或 Agent 时，希望它先沿我画好的结构走。

各块单独记一笔（方便复习）

大模型与天才员工比喻：后面所有概念都在回答「怎么把这个高能力新人变成自己人」。

Prompt：临时口头交代；2026 年对手写长 Prompt 的依赖下降，但系统内部仍大量存在。

Agent：给目标不盯过程；和「问一句答一句」差别最大。

Skill：SOP 手册；库越厚，AI 越像老员工。

MCP：统一门禁；Skill 管方法，MCP 管去哪拿数。

IDE：智能办公室；关键不是有没有补全广告，而是 Agent 能否可靠地读、改、测代码。

Claude Code / OpenCode：终端特种兵；OpenCode 更开放、可多模型。

四齿轮提效：LLM + Agent + Skill + MCP 同时转起来，工作方式才会变，而不是快一点点。
