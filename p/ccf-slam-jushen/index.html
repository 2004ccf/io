用大白话搞懂 SLAM 与具身智能

SLAM、VLA、VLN、FluxVLA 大白话笔记：从认路到具身智能。

Apr 30, 2026

我为什么整理这篇

SLAM、VLA、FluxVLA、VLN 这些词我老混在一起。so我整理的大白话笔记，和 逐际动力、人形零部件与五层架构、AI Agent 来时路 对照看。

一、核心基础概念

1. 上游感知基座模型（AI 的「眼睛」和「大脑」）

LLM（大语言模型）— Large Language Model

  • 我怎么说：就像 ChatGPT 那种只会读文字、写文字的 AI。我问它「今天吃什么」，它能回答，但它看不见我家厨房里的锅碗瓢盆。
  • 英文全称：Large Language Model（大语言模型）
  • 它干什么：理解语言、推理、做任务规划，但只输出文字，碰不到真实世界。

LVM（大视觉模型）— Large Vision Model

  • 我怎么说：只会看图片/视频的 AI。给它一张照片，它能认出「这是猫」「这是红绿灯」，但它不会说话、不会动。
  • 英文全称：Large Vision Model（大视觉模型）
  • 它干什么：图像分类、目标检测、理解场景，只输出视觉识别结果。

VLM（视觉-语言模型）— Vision-Language Model

  • 我怎么说：既能看又能说的 AI。我给它一张图，问「图里几个人？」，它能用文字回答。但它还是动不了手——只能聊天，不能帮机器人抓杯子。
  • 英文全称：Vision-Language Model（视觉-语言模型）
  • 它干什么：看图问答、图文推理，输出文字，不输出动作。

AGI（通用人工智能）— Artificial General Intelligence

  • 我怎么说：理想中的「什么都会一点的超级 AI」，像人一样能跨领域学习、推理。现在还远没完全实现，但人形机器人 + VLA 被认为是让 AGI 真正「走进物理世界」的重要方向。
  • 英文全称：Artificial General Intelligence（通用人工智能）

2. SLAM 通用基础（机器人怎么「认路」）

SLAM（同步定位与地图构建）— Simultaneous Localization and Mapping

  • 我怎么说：机器人第一次去一个陌生房间，一边走一边搞清楚两件事：

    1. 我在哪？（定位 — Localization）
    2. 周围长什么样？（建地图 — Mapping）

    就像我蒙眼进陌生房间，一边摸墙一边在脑子里画地图，还要随时知道自己走到哪了。

  • 英文全称：Simultaneous Localization and Mapping（同步定位与地图构建）

  • 核心逻辑：传感器采集环境 → 对比前后画面推算位置 → 拼出地图 → 用地图修正定位误差 → 循环往复。

  • 核心模块（我记这几个就够）：

    • 前端里程计 — Front-end Odometry：边走边算「我走了多远、转了多少」
    • 后端优化 — Back-end Optimization：把前面算的结果再精修一遍
    • 回环检测 — Loop Closure Detection：发现「咦，这地方我来过」→ 修正累计误差
    • 重定位 — Relocalization：跟丢了以后重新找自己在地图上的位置
    • 地图构建 — Map Building：把看到的东西拼成一张地图

  • 核心特性（容易出问题的点）：

    • 位姿漂移 — Pose Drift：越走越偏，像手机导航偶尔飘
    • 累计误差 — Accumulated Error：小误差叠加大误差
    • 尺度漂移 — Scale Drift：不知道真实距离是 1 米还是 10 米
    • 尺度恢复 — Scale Recovery：想办法找回真实尺寸
    • 退化场景 — Degenerate Scene：白墙、长走廊、大空地——没什么特征可认，传感器容易「瞎」

紧耦合 vs 松耦合 — Tight Coupling vs Loose Coupling

  • 紧耦合 — Tight Coupling（我理解为「一起算」）：
    • 多个传感器（相机、激光、IMU）的数据塞进同一个公式里一起算。
    • 像多个证人同时开会对口径 → 结果更准、更稳，但实现复杂。
  • 松耦合 — Loose Coupling（我理解为「各算各的再平均」）：
    • 每个传感器先自己算一遍，最后加权合并。
    • 像各证人分开写报告再汇总 → 简单省算力，但精度差一点。

3. 视觉 SLAM（vSLAM）——用摄像头认路

vSLAM — Visual SLAM

  • 我怎么说：SLAM 里主要靠摄像头完成定位和建图的那一支。
  • 英文全称：Visual SLAM（视觉同步定位与地图构建）

三种常见摄像头方案

方案英文全称我怎么说优缺点
单目 vSLAMMonocular Visual SLAM一个摄像头，像手机单摄最便宜最小，但不知道真实距离，常要配 IMU 补
双目 vSLAMStereo Visual SLAM两个摄像头，像人两只眼能算真实深度，有真实尺度，更准
RGB-D vSLAMRGB-Depth Visual SLAM深度相机（如 Kinect）直接给每个像素的距离，建图快，但看得不远

技术方法（知道名字就行）

  • 特征点法 — Feature-based Method：找图像里「角点、边缘」当路标
  • 直接法 — Direct Method：不找特征点，直接比像素亮度
  • 稀疏直接法 — Sparse Direct Method：直接法的轻量版
  • 点云配准 — Point Cloud Registration：把两帧 3D 点云对齐（激光 SLAM 常用）

地图类型

  • 稀疏特征地图 — Sparse Feature Map：只存关键点，省内存
  • 稠密点云地图 — Dense Point Cloud Map：密密麻麻的 3D 点，细节多
  • 占用栅格地图 — Occupancy Grid Map：把空间划成格子，标记「能走/不能走」
  • 语义地图 — Semantic Map：不仅知道「这里有块区域」，还知道「这是桌子、那是门」

4. 语义 SLAM — Semantic SLAM

  • 我怎么说：普通 SLAM 画出来的地图像毛坯房平面图——只有墙和空位；语义 SLAM 像带家具标注的平面图——「这里是桌子、那里是水杯、那是门」。
  • 英文全称：Semantic SLAM（语义同步定位与地图构建）
  • 为什么重要：这是 SLAM 和大模型、VLA 对接的桥梁——机器人不仅知道「在哪」，还知道「周围是什么东西」。

5. E2E（端到端）— End-to-End

  • 我怎么说：输入直接到输出，中间不拆很多手工模块。
    • 传统做法：看 → 识别 → 规划 → 控制（四五个模块串起来）
    • 端到端：看 + 听指令 → 直接出动作（一个模型搞定）
  • 英文全称：End-to-End（端到端）
  • 好处：少人工设计、泛化强、误差不会一层层叠加。
  • 坏处：像黑盒，不好解释；需要大量训练数据。
  • 典型应用：端到端 VLA、端到端 SLAM、端到端机器人控制。

6. VLN（视觉语言导航）— Vision-Language Navigation

  • 我怎么说：我对机器人说「去厨房拿红色杯子」，它自己看路、自己走过去——这就是 VLN。
  • 英文全称：Vision-Language Navigation（视觉语言导航）
  • 输入：我说的话 + 机器人第一视角看到的画面。
  • 输出：前进、左转、右转、停下……一串导航动作。
  • R2R（Room-to-Room） — Room-to-Room：VLN 领域常用的考试题库——在虚拟房间里测机器人能不能听懂指令找到目标。
  • 和 SLAM 的关系：SLAM 是底层认路；VLN 是在认路之上加了听懂人话、按语义找目标的能力。

7. VLA（视觉-语言-动作模型）— Vision-Language-Action

  • 我怎么说：VLM 只能「看+说」，VLA 更进一步——看 + 听懂 + 真的动手动脚。
    • 输入：画面 + 我的指令（比如「把杯子递给我」）
    • 输出：关节怎么转、手怎么张、底盘怎么动……全套动作参数
  • 英文全称：Vision-Language-Action（视觉-语言-动作）
  • 能力范围：能导航，也能抓东西；能控制全身人形机器人；包含 VLN 的能力。

Loco-Manipulation（全身移动操作）— Locomotion + Manipulation

  • 我怎么说：人形机器人一边走一边干活，不是「先走到地方 → 停下来 → 再伸手」。
    • 比如：边走向桌子边伸手拿杯子。
  • 英文全称：Loco-Manipulation（Locomotion 移动 + Manipulation 操作）
  • 为什么重要：这是衡量人形机器人成不成熟的核心标志之一。

8. Baseline（基线/基准方案）— Baseline

  • 我怎么说：行业里的**「标准答案/参照物」**——新算法出来，要和它比谁更好；做项目也常从它改起。
  • 英文全称：Baseline（基线/基准方案）
  • 常见 Baseline（我查资料时对照这些）：
    • 视觉 SLAM：ORB-SLAM3 — Oriented FAST and Rotated BRIEF SLAM 3
    • 视觉惯性里程计：VINS-Mono — Visual-Inertial Navigation System Mono
    • 激光 LIO：FAST-LIO2 — Fast LiDAR-Inertial Odometry 2
    • VLN：R2R 数据集上的经典模型 — Room-to-Room Dataset
    • VLA：OpenVLA — Open Vision-Language-Action；Google RT-1 — Robotics Transformer 1

二、主流 SLAM 算法与方案

（一）核心基础算法术语（我用生活例子记）

里程计 — Odometry

  • 我怎么说：机器人自己的「计步器」——根据传感器增量数据，推算「走了多远、转了多少」。
  • 英文全称：Odometry（里程计）
  • 分类：
    • 视觉里程计 — Visual Odometry（靠摄像头）
    • 激光里程计 — LiDAR Odometry（靠激光）
    • 惯性里程计 — Inertial Odometry（靠 IMU）

VIO（视觉惯性里程计）— Visual-Inertial Odometry

  • 我怎么说：摄像头 + IMU（惯性单元）绑在一起算，像「眼睛看路 + 内耳感知平衡」配合，比单摄像头稳。
  • 英文全称：Visual-Inertial Odometry（视觉惯性里程计）

LIO（激光惯性里程计）— LiDAR-Inertial Odometry

  • 我怎么说：激光雷达 + IMU 绑在一起算，激光负责精确测距，IMU 负责快速运动时不丢。
  • 英文全称：LiDAR-Inertial Odometry（激光惯性里程计）

光束法平差（BA）— Bundle Adjustment

  • 我怎么说：视觉 SLAM 的「精修环节」——同时调整相机位置和地图上的点，让「3D 点投影到照片上」和「实际看到的点」尽量重合。
  • 英文全称：Bundle Adjustment（光束法平差）

图优化 — Graph Optimization

  • 我怎么说：把 SLAM 问题画成一张网：每个节点是一个位置，每条边是一个约束，然后整体找最优解。
  • 英文全称：Graph Optimization（图优化）
  • 我记：后端优化的主流做法。

词袋模型（BoW）— Bag of Words

  • 我怎么说：像「视觉版的关键词匹配」——判断「这地方我来过吗？」通过比较两帧图像的特征相似度。
  • 英文全称：Bag of Words（词袋模型）
  • 用途：回环检测 — Loop Closure Detection（发现回到老地方）

IMU 预积分 — IMU Pre-integration

  • 我怎么说：IMU 数据更新很快（几百 Hz），如果每次都从头积分太慢；预积分就是提前算好一段，后面直接用，省计算。
  • 英文全称：IMU Pre-integration（IMU 预积分）
  • 我记：VIO 里的提速技巧。

ESIKF — Error State Iterated Kalman Filter

  • 我怎么说：一种高效滤波算法，激光/多传感器融合 SLAM 里常用——算得快、数值不容易崩。
  • 英文全称：Error State Iterated Kalman Filter（误差状态迭代卡尔曼滤波）

视觉重投影误差 — Visual Reprojection Error

  • 我怎么说：3D 地图点「投影」到照片上，和实际特征点差几个像素——差越小越好，这是视觉 SLAM 优化的核心指标。
  • 英文全称：Visual Reprojection Error（视觉重投影误差）

点云配准 — Point Cloud Registration

  • 我怎么说：激光 SLAM 里，把前后两帧 3D 点云对齐，算出机器人动了多少。
  • 英文全称：Point Cloud Registration（点云配准）

Sim2Real（仿真到真机迁移）— Simulation to Reality

  • 我怎么说：先在电脑仿真环境里大量训练（便宜、安全、可重复），再搬到真机器人上用——降低 VLA、SLAM 的训练成本。
  • 英文全称：Simulation to Reality（仿真到真机迁移，简称 Sim2Real）

（二）纯视觉/视觉惯性 SLAM

1. ORB-SLAM 系列 — Oriented FAST and Rotated BRIEF SLAM

  • 谁做的：西班牙萨拉戈萨大学 Raul Mur-Artal 团队。
  • 英文全称：Oriented FAST and Rotated BRIEF SLAM
  • ORB 特征 — Oriented FAST and Rotated BRIEF：从图像里找「好认的角点」当路标。
    • FAST — Features from Accelerated Segment Test（加速段测试特征）
    • BRIEF — Binary Robust Independent Elementary Features（二进制鲁棒独立基本特征）
  • 版本：
    • ORB-SLAM2：支持单目/双目/RGB-D，最经典的入门 Baseline。
    • ORB-SLAM3：加了 IMU、多地图、鱼眼相机，更稳更准。
  • 优点：纯视觉就能跑，回环检测好，长时间漂移小。
  • 缺点：白墙、快速运动容易跟丢。
  • 我记：特征点法视觉 SLAM 的行业标杆。

2. VINS 系列 — Visual-Inertial Navigation System

  • 谁做的：港科大沈劭劼团队。
  • 英文全称：Visual-Inertial Navigation System（视觉惯性导航系统）
  • 我怎么说：相机 + IMU 紧耦合的标杆，解决单目相机「不知道真实距离、容易丢」的问题。
  • 怎么工作：前端提取视觉特征 + IMU 预积分 → 后端滑动窗口优化 — Sliding Window Optimization → 让视觉误差和 IMU 误差一起最小。
  • 版本：
    • VINS-Mono：单目 + IMU，经典 VIO，能恢复真实尺度。
    • VINS-Fusion：支持双目、GPS 等，扩展更强。
  • 常见用途：人形机器人、无人机、AR/VR — Augmented Reality / Virtual Reality（增强现实/虚拟现实）

3. Cartographer — Cartographer

  • 谁做的：谷歌 — Google
  • 英文全称：Cartographer（制图者，谷歌开源激光 SLAM 框架名）
  • 我怎么说：开源激光 SLAM 框架，工程成熟、稳定，支持 ROS/ROS2，2D/3D 都能建。
  • 常见场景：仓储 AGV — Automated Guided Vehicle（自动导引车）、服务机器人、室内巡检。

（三）激光与多传感器融合 SLAM

1. FAST-LIO 系列 — Fast LiDAR-Inertial Odometry

  • 谁做的：香港大学 MaRS 实验室张富教授团队。
  • 英文全称：Fast LiDAR-Inertial Odometry（快速激光惯性里程计）
  • 我怎么说：激光雷达 + IMU 紧耦合的工业级标杆——快、稳、算力要求相对低。
  • 地位：R3LIVE、FAST-LIVO、LVI-SAM 等方案的底层 LIO 底座。
  • 我记版本：FAST-LIO2 是行业通用 Baseline。

2. R3LIVE — Robust, Real-time, RGB-colored, LiDAR-Inertial-Visual tightly-coupled state Estimation

  • 英文全称：Robust, Real-time, RGB-colored, LiDAR-Inertial-Visual tightly-coupled state Estimation and mapping（鲁棒实时彩色激光-惯性-视觉紧耦合状态估计与建图）
  • 谁做的：港大 MaRS 团队。
  • 我怎么说：激光 + IMU + 相机三个传感器一起算，输出带颜色的稠密 3D 地图，精度高。
  • 架构：LIO 子系统（FAST-LIO，负责定位）+ VIO 子系统（相机补颜色）。
  • 优点：快速运动、光线剧变也能扛。
  • 缺点：算力吃得比较多。
  • 用途：工业巡检、三维重建 — 3D Reconstruction、高精度机器人。

3. LVI-SAM — LiDAR-Visual-Inertial Smoothing and Mapping

  • 英文全称：LiDAR-Visual-Inertial Smoothing and Mapping（激光-视觉-惯性平滑与建图）
  • 我怎么说：激光 + 视觉 + IMU 紧耦合，基于 FAST-LIO 和 VINS 框架搭的。
  • 我记：多传感器融合 SLAM 的对比基准，常用来和 R3LIVE、FAST-LIVO2 比性能。

4. FAST-LIVO — Fast LiDAR-Inertial-Visual Odometry

  • 谁做的：港大 MaRS 团队。
  • 英文全称：Fast LiDAR-Inertial-Visual Odometry（快速激光-惯性-视觉里程计）
  • 我怎么说：R3LIVE 的轻量版——给嵌入式/移动端用的，ARM 芯片也能实时跑。
  • 特点：视觉用稀疏直接法，ESIKF 统一融合框架。

5. FAST-LIVO2 — Fast LiDAR-Inertial-Visual Odometry 2

  • 谁做的：港大 MaRS 团队，论文发在 IEEE Transactions on Robotics（IEEE 机器人汇刊），还拿了傅京孙纪念最佳论文奖 — Fu King-Sun Memorial Best Paper Award。
  • 英文全称：Fast LiDAR-Inertial-Visual Odometry 2
  • 我怎么说：目前工业落地性很强的轻量化多传感器融合方案——比 R3LIVE、LVI-SAM 更准，还更快更省内存。
  • 五大升级（知道方向就行）：
    1. ESIKF 顺序更新 → 快速运动更稳
    2. 激光平面先验 — LiDAR Plane Prior → 视觉对齐更准
    3. 动态更新参考补丁 — Dynamic Reference Patch Update → 减少对齐误差
    4. 在线曝光估计 — Online Exposure Time Estimation → 光线变化不怕
    5. 体素光线投射 — Voxel Raycasting → 补激光近距盲区
  • 性能数据：单帧耗时降 33%，内存降 47%。

（四）SLAM 配套增强工具

M-detector — Motion Detector

  • 谁做的：港大 MaRS 团队，论文发在《Nature Communications》（自然·通讯）。
  • 英文全称：Motion Detector（运动检测器）
  • 我怎么说：激光雷达的「动态物体过滤器」——逐点判断「这个点是静止的墙，还是那个在走的人」，把动的东西滤掉，SLAM 只建静态环境的图。
  • 为什么重要：人流、车流多的场景，普通 SLAM 容易被「动的东西」搞乱；M-detector 延迟只有微秒级，实时性很好。
  • 常搭配：FAST-LIO 系列一起用。

2. 雷达类传感器

RADAR（毫米波雷达）— Radio Detection and Ranging

  • 我怎么说：发无线电波测距测速，雨雾天也能用，能穿透，但分辨率低——不适合做主 SLAM，主要做障碍物检测和备份感知。
  • 英文全称：Radio Detection and Ranging（无线电探测与测距）

LiDAR（激光雷达）— Light Detection and Ranging

  • 我怎么说：发激光束，测距超准、点云超清晰，高精度 SLAM 的核心传感器，就是比较贵。
  • 英文全称：Light Detection and Ranging（光探测与测距）

3. 惯性与本体传感器

IMU（惯性测量单元）— Inertial Measurement Unit

  • 我怎么说：机器人里的「内耳」——测三轴加速度 + 三轴角速度，帮摄像头/激光在快速运动、短暂遮挡时不丢。
  • 英文全称：Inertial Measurement Unit（惯性测量单元）

关节编码器 — Joint Encoder

  • 我怎么说：人形机器人每个关节上的「角度传感器」，告诉系统「这个关节现在转了多少度」，辅助视觉 SLAM 恢复真实尺度。
  • 英文全称：Joint Encoder（关节编码器）

33 维本体状态 — 33-Dimensional Proprioceptive State

  • 我怎么说：机器人当前全身状态的一个数字打包——典型是 31 个关节位置 + 左右手开/合标志，共 33 个数。
  • 英文全称：33-Dimensional Proprioceptive State（33 维本体感知状态）

42 维全身动作指令 — 42-Dimensional Whole-body Action Command

  • 我怎么说：告诉机器人下一步怎么动的数字打包——31 个关节目标位置 + 底盘 base_link 的位置和旋转 + 双手开合，共 42 个数。
  • 英文全称：42-Dimensional Whole-body Action Command（42 维全身动作指令）

base_link — Base Link

  • 我怎么说：机器人身体的**「根坐标系」**——其他部位的位置都相对它来说的，像「以躯干为中心描述全身」。
  • 英文全称：Base Link（基座链接坐标系，ROS 标准坐标系名称）

4. 人形机器人硬件平台

LimX Oli — LimX Oli

  • 我怎么说：逐际动力 — LimX Dynamics 做的全尺寸人形机器人，FluxVLA Engine 的配套真机——可以在上面跑全身移动操作（Loco-Manipulation） 的真机推理。
  • 英文全称：LimX Oli（逐际动力人形机器人产品名）

四、工程框架与开发环境

1. ROS 系列机器人中间件

ROS1（第一代机器人操作系统）— Robot Operating System

  • 我怎么说：机器人界的「Windows XP」——经典、生态大，但老了。
  • 英文全称：Robot Operating System（机器人操作系统）
  • rospy — ROS Python：用 Python 写 ROS 程序的接口，适合快速写传感器读取、逻辑控制。
  • 常用工具：
    • RViz — ROS Visualization（ROS 可视化工具）：3D 可视化，看地图、看机器人
    • Gazebo — Gazebo Simulator（Gazebo 仿真器）：机器人仿真环境，先在电脑里跑
  • 缺点：不支持硬实时 — Hard Real-time、只能单机、稳定性一般 → 逐渐被 ROS2 替代。

ROS2（第二代机器人操作系统）— Robot Operating System 2

  • 我怎么说：机器人界的「Windows 11」——现在做 SLAM 真机落地，基本都用它。
  • 英文全称：Robot Operating System 2（第二代机器人操作系统）
  • 核心升级：底层换成 DDS 通信协议 — Data Distribution Service（数据分发服务）→ 支持硬实时、多机协同、跨平台。
  • 标准消息类型：
    • sensor_msgs — Sensor Messages（传感器消息格式）
    • geometry_msgs — Geometry Messages（几何/位姿消息格式）
  • 对我有什么用（5 点）：
    1. 传感器接入标准化，不用每个硬件单独写驱动
    2. 发布-订阅机制 — Publish-Subscribe，模块之间松耦合，换算法不用重写整个系统
    3. 有 RViz2、rqt — ROS Qt GUI Toolkit 调试工具，调 SLAM 方便
    4. 对接 Nav2 导航栈 — Navigation2 → 建图-定位-导航-运动一条龙
    5. 支持分布式、多机器人协同
  • WebSocket JSON 协议 — WebSocket + JSON（JavaScript Object Notation，JavaScript 对象表示法）：LimX Oli 人形机器人的控制指令下发方式。

4. 本地开发环境工具

WSL2（Windows Linux 子系统 2）— Windows Subsystem for Linux 2

  • 我怎么说：在 Windows 里嵌一个 Linux——秒开、省资源、和 Windows 文件互通，适合编译代码、轻量开发。
  • 英文全称：Windows Subsystem for Linux 2（Windows Linux 子系统 2）
  • 缺点：RViz、Gazebo 等 3D 可视化性能差，硬件直通一般 → 适合编译，不适合重度仿真。

VM 虚拟机软件 — Virtual Machine

  • 代表：
    • VMware Workstation — VMware 工作站虚拟机
    • VirtualBox — Oracle VirtualBox 虚拟盒
    • Parallels Desktop — Parallels 桌面虚拟机（Mac 常用）
  • 英文全称：Virtual Machine（虚拟机）
  • 我怎么说：在电脑里虚拟出一台完整电脑，装完整 Linux 系统——功能全、隔离好、能 USB 直通、能快照回滚 — Snapshot。
  • 缺点：占资源多、启动慢。
  • 适合：完整 Linux 桌面、Gazebo 重型仿真、接外接硬件调试。

我选哪个：日常编译用 WSL2；要跑 Gazebo 仿真、接硬件用 VM。
