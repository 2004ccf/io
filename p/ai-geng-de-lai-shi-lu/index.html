AI Agent 的来时路：从 ChatGPT 到 Hermes

2022–2026 AI Agent 五代演进编年史：Function Calling、ReAct、MCP、Vibe Coding、OpenClaw、Hermes 与泡沫事故年鉴。

Apr 30, 2026

我为什么会整理这篇

2022 年大家还在聊 ChatGPT 对话框，到 2026 年已经在谈常驻 Agent、MCP、Skill、OpenClaw——名词换了好几轮，我很容易把不同年代的产品混成一锅。看完 《AI Agent 五代演变万字拆解》之后，我决定按时间线把关键节点记下来，方便自己和别人对照：每一次跃迁到底是模型变强、工具成熟，还是工程架构在

我带着的四个问题

  1. 同样叫 AI，为何 2022 ChatGPT 与 2026 Agent 形态完全不同？
  2. 每次跃迁是模型变强、工具成熟，还是工程架构变？
  3. 为何反复出现炒作泡沫（提示词工程师、GPT Store 等）？
  4. 什么是真护城河？哪些中间层会被下一代基础设施吞噬？

一、总览：五代 + 一代前瞻

世代时间关键词本质变化
第 0 代2022 末 – 2023 初对话框里的超级大脑能想能说，不能行动
第 1 代2023 中 – 2023 末工具调用觉醒大脑 + 四肢第一次合体
第 2 代2023 末 – 2024工程化编排从黑盒魔法到可控工作流
第 3 代2024 Q4 – 2025标准协议 + 行动空间革命API 世界 → GUI/CLI 真实操作
第 4 代2025 末 – 2026 初技能封装 + 常驻自治从「叫才动」到像员工
第 5 代（前瞻）2026+闭环 / 内在记忆 / 世界模型 / 具身尚未定型，逻辑推演

2026 前沿代表：Hermes Agent（Nous Research）——常驻、自改进、Curator 维护技能库，把「员工形态」推向「会成长的数字员工」。

二、分代详解：应用 / 技术名称 + 优劣势

下表「类型」：应用=可安装/订阅产品；技术=协议/范式/API；框架=开发库；泡沫=曾热后萎缩的中间层。

第 0 代：2022 年末 – 2023 年初

架构：超级大脑困在对话框。核心矛盾：模型能力与现实世界断裂。

名称类型简介优势缺点
ChatGPT应用2022-11-30 发布零门槛；引爆全民使用；多轮对话体验好知识截止、幻觉；不能执行（不跑代码、不改本地文件、不订票）
GPT-3模型技术圈已知能力已验证生成/问答未产品化，普通用户用不了
GPT-4模型2023 起逐步可用模糊指令理解大幅提升，挤压提示词稀缺性贵；仍无行动臂
提示词工程技术+职业CoT、角色设定、分步指令早期模型下真实有效被误判为永久护城河；约一年内中间层蒸发
Promptbase 等应用/市场售卖模板、课程、认证降低学习成本模板易被内化复制，无壁垒
Chain-of-Thought研究范式2022 Google 等多步推理显著提升仍只输出文本，无行动
ReAct研究范式2022 Google：推理+行动循环奠定后续 Agent 循环理论基础当时未产品化

泡沫：提示词工程师（2023 上半年） → 详见 §5.1

  • 假设：高效交互需要不可替代的专业技艺。
  • 现实：GPT-4 + System Prompt + Function Calling 接管精细控制。
  • 剧本：临时补丁 → 被当成护城河 → 基础设施内化后中间层蒸发（此后每代重演）。

第 0 代 · 补充详解（研究脉络）

名称说明
Tree of Thoughts（ToT）2023 Yao 等：多分支推理、评估、回溯；部分谜题准确率 4%→74%。优势：复杂推理；缺点：成本高，未成为主流产品形态。
Self-Consistency多次采样取众数，提高可靠性；缺点：成倍 token。
InstructGPT / RLHFChatGPT 能「听话」的基础；属第 0 代能力底座，非 Agent。

第 1 代：2023 年中 – 2023 年末

关键词：工具调用觉醒。Agent 最小结构：角色是谁 + 知道什么 + 能做什么。

名称类型时间/背景优势缺点
Function Calling技术/API2023-06-13 OpenAI结构化 JSON 调 API；模型自选工具与参数需开发者定义 schema；错误调用要应用层兜底
RAG技术范式与 FC 同期接私有/最新文档；动态知识外挂检索，非真记住；切片与召回质量敏感
Pinecone向量库应用RAG 热潮托管省心、生态成熟成本高；被长上下文质疑「是否必需」
Milvus向量库开源可自建私有部署、性能好运维复杂；难单独构成护城河
LlamaIndex框架文档→向量→检索快速搭 RAG 原型生产需额外工程
ChatGPT Plugins产品功能2023-03第三方进对话；模型即平台雏形后被弃用；集成碎片化
Custom Instructions产品功能2023-08持久化偏好（如默认 Python）浅层 Persona，非完整记忆
GPTs应用2023-11低门槛定制 Bot多为提示词+PDF，无工作流
Assistants API开发者 API2023-11系统提示+检索+工具三位一体厂商锁定；复杂任务需自建编排
AutoGPT开源 Agent2023 月内 GitHub 5 万+ star宏大目标→拆解→循环；演示震撼开环：任务迷失、重复错误 API、账单燃烧；生产不可用
BabyAGI开源 Agent2023-04 前后创建/排序/执行三 Agent；比 AutoGPT 更聚焦规划仍非生产级；社区热度低于 AutoGPT
AgentGPT开源/网页2023浏览器里跑自主循环，零代码体验同族开环与成本问题
Toolformer研究/模型能力Meta 2023模型自学何时调用工具，FC 的思想先驱非开箱产品
LangChain框架2023 爆发模块化链与 Agent 封装此阶段已现抽象过重苗头

第一代教训：工具 + 死循环 ≠ Agent；须引入状态、终止条件、评估、人机节点。

第 1 代 · 补充详解

BabyAGI（2023-03~04，Yohei Nakajima）

  • 架构：三 Agent——任务创建、优先级排序、执行；结果写入向量库（常配合 Pinecone）形成「任务记忆」。
  • 优势：代码极简（早期 <100 行 Python），适合教学；显式「先规划再执行」，比 AutoGPT 更少「兔子洞」。
  • 缺点：无生产级错误处理；工具集成弱；仓库已 archive，作者转向 BabyAGI 2/3 实验。
  • 与 LangChain 关系：LangChain 官方曾对比——BabyAGI 用显式任务队列对抗长任务中的目标遗忘。

AgentGPT（2023-04）

  • 定位：浏览器内一键跑自主循环，面向非开发者。
  • 优势：零安装、演示极快。
  • 缺点：与 AutoGPT 同源问题——开环、成本、不可靠；热度随 AutoGPT 降温而下降。

Toolformer（Meta，2023 论文）

  • 意义：模型自监督学习何时调用计算器、搜索等工具，是 Function Calling 的学术先驱。
  • 优势：证明「工具使用」可内化进模型行为。
  • 缺点：停留在研究/训练范式，开发者仍依赖 OpenAI FC 等产品化 API。

SuperAGI（2023）

  • 定位：带 GUI 的开源自主 Agent 平台（安装、工具、记忆一站式）。
  • 优势：比裸 AutoGPT 多了产品壳与监控。
  • 缺点：本质仍是自主循环；社区声量远小于 LangChain/AutoGPT，生产案例少。

向量库赛道补充

  • Pinecone：2023-04 B 轮 1 亿美元，估值 7.5 亿美元（TechCrunch / Bloomberg）；累计融资约 1.38 亿美元。客户含 Shopify、Gong、HubSpot、Zapier。
  • 争议：2024 起 Gemini 1.5、Claude 等 百万级上下文 出现后，「是否还需要向量库」成行业辩论；共识走向 混合检索（向量 + 关键词 + 长上下文片段）。
  • Chroma、Weaviate、Qdrant 等：同赛道竞争者，优势在开源/自建，缺点在需运维与商业化不及 Pinecone 早期声势。

第 2 代：2023 年末 – 2024 全年

关键词：工程化编排。追求确定性；Agent = 有控制流、状态、反馈的软件系统。

2.1 范式与设计模式

名称类型优势缺点
ReAct范式Thought→Action→Observation；可审计多轮调用，成本与延迟
ReflectionAgentic 模式写稿→审稿→修改，提质双倍 token
Tool UseAgentic 模式主动选搜索/DB/代码/API工具过多则选型噪声
PlanningAgentic 模式拆目标、追踪状态计划易过时
Multi-AgentAgentic 模式角色分工（CEO/程序员/QA）无边界则放大噪声与成本（至今适用）

重要结论：设计良好的 Agentic Workflow + 较小模型，可碾压裸跑大模型。

2.2 框架与多 Agent 项目

名称类型优势缺点
LangChain框架7 万+ star；创业默认栈抽象过重、回调复杂、难调试（「三行变 30 行」）
LangGraph框架状态机、循环、checkpoint、人机协同学习曲线高
ChatDev项目模拟软件公司协作开发演示性强，交付不稳定
CrewAI框架角色/目标/背景清晰复杂编排可观测性弱于 LangGraph
AutoGen框架（微软）灵活对话、可插人配置复杂、成本难控
Devin商业 Coding Agent2024-03；沙箱+浏览器+终端；SWE-bench 无辅助 ~13.86%意图误解、死循环烧额度、架构/隐性规范弱、云端治理与 ACU 计费不透明

2.3 长上下文争论

名称类型优势缺点
Gemini 1.5 Pro模型~200 万 token，可整段塞入注意力稀释（上下文腐烂）；成本延迟上升
Context Engineering方法论RAG 精确检索 + 长上下文片段组合需团队设计，非开箱

2.4 低代码 / 工作流平台

名称类型优势缺点
Coze（扣子）低代码极速搭 Bot/多 Agent；字节生态（飞书、抖音）难私有化；企业 IAM 弱；流程易被复制
Dify低代码/开源可自建、RAG/Agent 成熟、企业向部署运维成本高
Flowise低代码可视化 LLM 应用护城河弱
Flowith平台可视化 Agent 流同低代码共性问题
n8n工作流通用自动化强，可接 AIAgent 深度不如 Dify 专精
ComfyUI节点式 UI生成式工作流；偏图像等多模态

低代码共性缺点：拖拽工作流可无成本复制；Vibe Coding 兴起后「只降 UI 不降复杂度」更显尴尬。

2.5 评测革命

名称类型测什么意义
MMLU 等传统基准静态选择题不能代表 Agent「能做成」
WebArena基准自托管电商/论坛/CMS 仿真真实环境任务
OSWorld基准真实 OS 键鼠操作计算机使用能力
GAIA基准人易 AI 难的综合推理推动端到端评估

第二代泡沫：LangChain Wrapper 批判；数十家零/低代码平台洗牌。→ 详见 §5.5、§5.6

第 2 代 · 补充详解

Semantic Kernel（微软，2023 起）

  • 定位：.NET / Python 双栈，面向 Azure OpenAI 的企业 Agent 编排。
  • 优势：与 Microsoft 365、Azure 身份与合规集成深；适合已买 Azure 的企业。
  • 缺点：GitHub star 与社区教程量明显低于 LangChain；非 Azure 团队迁移成本高。

HuggingFace Agents / Transformers Agents（2024）

  • 定位：在 HF 模型 Hub 上直接选模型 + 工具调用。
  • 优势：开源模型友好、可本地跑 Llama 等。
  • 缺点：企业级编排、观测、权限不如 LangGraph/CrewAI 成熟。

Plan-and-Execute 范式

  • 流程：Planner 先产出完整步骤 → Executor 逐步执行（LangChain 等有封装）。
  • 优势：比逐步 ReAct 更稳，适合步骤清晰的任务。
  • 缺点：计划一旦错，后面全偏；动态环境需频繁重规划。

LangGraph vs LangChain（社区共识 2025–2026）

维度LangChainLangGraph
范式链 / DAG显式状态机 + 循环
人机协同部分Checkpoint 原生
适用RAG、简单 Bot复杂 Agent、生产

CAMEL / Generative Agents（学术，2023）

  • CAMEL：角色扮演式多 Agent 对话，启发 ChatDev 等。
  • Generative Agents（斯坦福小镇）：长期记忆 + 日程，证明「社会模拟」可行。
  • 缺点：算力与工程成本高，难直接进企业生产。

第 3 代：2024 Q4 – 2025 全年

关键词：标准协议 + 行动空间革命。解决 Agent 如何连外部 与 如何操作真实软件。

名称类型时间优势缺点

A2A（补充）协议Google 2025 等Agent 之间互操作

名称类型时间优势缺点

3.3 通用智能体与编程文化

名称类型优势缺点
Manus通用自主 Agent虚拟机内调研/代码/分析/内容；市场为执行付费慢；编码深度不如专业 Coding Agent；额度难预测

第 3 代 · 补充详解

  • 事件：开源推理模型，性能对标 o1；MIT 许可；API 价约为同类 1/10~1/20；发布日曾引发市场对算力需求的剧烈波动（媒体报道 NVIDIA 单日大跌等）。

5.1 第 0 代：提示词工程师与 Promptbase（2023 上半年）

发生了什么

  • 2023-04：Anthropic 发布「Prompt Engineer & Librarian」岗位，媒体报道年薪可达 $250K–$375K（甚至流传 $500K 极端案例）。
  • 社会反应：LinkedIn「prompt engineer」搜索在 3 个月内暴涨 7000%+（多家媒体报道）；周末培训班、Promptbase 模板市场、认证课程蜂拥而至。
  • OpenAI 高管（如 Altman）称 prompt 是「高杠杆技能」，进一步放大 FOMO。

为何看起来像护城河

  • GPT-3.5/早期 GPT-4 对模糊提问极敏感；Chain-of-Thought（「请一步步思考」）对数学题等提升明显。
  • 企业确实需要有人写 System Prompt、Few-shot 样例——这是真实需求。

为何破灭（2023 下 – 2024）

因素说明
GPT-4 理解力模糊指令容忍度上升，手工雕 prompt 边际收益下降
产品内化System Prompt、Custom Instructions、Function Calling 把「控制」收进产品
岗位吸收能力并入 AI Engineer / ML Engineer；Microsoft 调研 3.1 万人：「prompt engineer」在计划新增岗位中倒数第二
搜索量崩塌Indeed：2023-04 峰值约 144次/百万搜索 → 2025 约 20–30（降幅 80%+）

教训

临时补丁被当成永久护城河；基座内化某能力后，围绕它的培训、模板、中间商系统性蒸发。

对创业者

  • 卖「万能提示词包」长期不可防御；可转向 垂直工作流 + 数据飞轮（见 §七）。

5.2 第 1 代：AutoGPT 狂热（2023）

发生了什么

  • 2023-03~04：Toran Bruce Richards 发布 AutoGPT；约 一个月 GitHub 5 万+ star
  • 同期 BabyAGI、AgentGPT 形成「自主 Agent 三连发」。
  • 演示：给一个宏大目标 → 自动搜索、写文件、自我评估 → 「AI 终于会自己干活了」。

技术机制（为何会火）

1

用户目标 → LLM 规划 → 选工具(浏览/写文件/执行) → 观察结果 → 再规划 → …
  • 比 ChatGPT 多了一层 闭环企图；叠加 GPT-4 的推理，观感接近科幻。

失败机制（为何迅速破灭）

问题具体表现
开环控制缺硬终止条件；错误 API 参数反复重试（「兔子洞」）
记忆缺陷有限上下文 + 弱长期记忆 → 忘记原始目标（Karpathy 指「有限上下文窗口」）
成本每步至少 1 次 GPT-4 调用；复杂任务 50 步 × 满 8K 上下文 可至 ~$14/次（社区估算）；死循环时 数小时数百美元（运维案例：6 小时 $127、45 分钟 $340）
不可复用无法把成功轨迹沉淀为函数；每次从零烧 token
幻觉与分心Wikipedia 记载：易幻觉、易分心、ChaosGPT 等恶搞项目引发伦理讨论

行业转折

  • 推动 ReAct（可审计每步）、LangGraph（显式状态机）、人机 checkpoint 成为标配。
  • 结论：工具 + 死循环 ≠ Agent。

5.3 第 1 代：GPT Store（2024-01）

发生了什么

  • 2024-01-10 OpenAI 上线 GPT Store，类比 App Store；宣布 Q1 2024 启动创作者分成（后一再延迟）。
  • 短时间大量用户创建 GPT；公开 GPT 数量达 十万级，商店内精选 数万。

泡沫叙事

  • 「做 GPT 月入过万」「百万定制 GPT 创业者」类内容泛滥。
  • 典型 GPT = System Prompt + 上传 PDF + 可选 Actions。

破灭证据（2024–2025）

现象数据/事实
分成试点极小长期仅 美国 等少数地区；需达 周 25 次对话 等门槛；<1% 创作者有收入（社区分析）
头部集中多数 GPT <10 次对话；真正 Featured 的是 Consensus、Grimoire 等少数
非美创作者如菲律宾开发者做 269 个 GPT（含 Featured Books GPT）仍无法变现（WIRED 等报道）
创作者转向用 GPT 作引流 → 咨询、课程、独立付费墙；OpenAI 池子分成不如直销

根本原因

  • 底层模型同质化 → 提示词不构成壁垒
  • 无工作流、无数据飞轮、无业务闭环 → 无法沉淀用户关系

教训

平台流量红利 ≠ 结构性护城河；中间层套壳在模型升级时最先死亡。

5.4 第 1 代：向量数据库估值狂欢（2023–2024）

发生了什么

  • RAG 成为企业 AI 默认架构；「向量库 = AI 时代数据库」 叙事流行。
  • Pinecone：2023-04 Series B $1 亿，估值 $7.5 亿（a16z 领投）。
  • Milvus/Zilliz、Weaviate、Chroma 等同步融资热。

争议（2024 起）

  • Gemini 1.5 等支持 ~200 万 token → 「整库塞进上下文还要向量吗？」
  • 行业答案分化后收敛：混合检索——向量/recency/关键词 + 长上下文承载连贯段落。

未完全「灭绝」的原因

  • 百万 token 仍贵、慢，且有 注意力稀释；
  • 企业知识库常 百万页级，全量塞入不现实；
  • 权限/filter 元数据检索向量更合适。

教训

把「向量检索」单独当永恒护城河过于乐观；价值迁到 端到端 RAG 管线 + 领域数据。

5.5 第 2 代：LangChain 与「Wrapper 批判」（2023 末–2024）

发生了什么

  • LangChain 成为 AI 创业 默认技术栈；GitHub 7 万+ star。
  • 社区吐槽：「三行能搞定的事要写 30 行 + 三层回调」。

具体问题

问题影响

回调/链式调用异常栈深、可观测性差

  • 部分团队 弃框架 → 直接 OpenAI SDK + 自写 200 行编排（「boring technology」回归）。

框架降门槛，但若抽象无稳定边界，会成为新的复杂性来源。

5.7 第 3 代：Vibe Coding 宿醉（2025）

起源

  • 2025-02，Andrej Karpathy 推文：「Vibe Coding」——沉浸 vibe，用自然语言表达意图，可「忘记代码存在」。

文化意义

  • AI 编程从补全 → 意图驱动生成；降低原型门槛。

METR 研究

指标数值
设计16 名有经验开源开发者，246 个真实 issue，成熟仓库（均 100 万+ 行）
工具Cursor Pro + Claude 3.5/3.7 Sonnet（2025-02~06）
实际耗时允许 AI 后任务完成时间 +19%（更慢）
事前预测开发者以为会快 24%
事后自评仍以为快了 20%
专家预测经济学家/ML 专家曾预测快 38~39%——全部落空

时间去哪了

  • 生成快了，但 prompt、审查、修幻觉、对齐架构 吞噬收益。
  • 研究术语：「Fast and Spurious」——虚假的速度感。

与 Kepler/Kiro 的关联

  • 媒体称 Kiro「vibed too hard」——在修复小 bug 时采取「删库重建」式方案，类似 过度自信的生成式修复。

铁律

  • 代码能跑 ≠ 架构健康；须 测试、审查、回滚、评估驱动开发（EDD）。
  • 企业应度量 交付周期 而非 打字速度。

5.8 第 3 代：Kepler / Kiro 事故（2025-12）

「Kepler」；公开报道多指亚马逊内部工具 Kiro（2025-07 发布的 Agentic 编码产品）。以下合并叙述。

时间线

时间事件
2025-07AWS 发布 Kiro Agentic 编码助手
2025-12 中旬工程师用 Kiro 修 AWS Cost Explorer（账单分析服务）小 bug
同期Agent 判定最优解 = 删除并重建整个环境（非打补丁）
结果中国大陆区域 Cost Explorer 约 13 小时不可用；计算/存储等核心服务未波及

治理失败点（多方分析一致）

  1. 权限过大：工程师角色可绕过 双人审批（two-person rule）
  2. 自主执行过快：机器速度下人类来不及拦截
  3. 策略缺失：无「禁止对生产环境执行 delete-env」类策略护栏
  4. 非孤立事件：FT 引 AWS 员工称数月内 第二起 AI 工具相关生产事件（第一起涉 Amazon Q Developer）

亚马逊官方回应（2026 初）

  • 归因 「用户错误 / 权限配置错误」，非「AI 失控」；强调 Kiro 默认需授权。
  • 已追加：生产环境强制 peer review、权限审计、培训。

行业解读

  • 核心不是「模型笨」，而是 自治 + 高权限 + 无沙盒 的组合爆炸。
  • 即便人类点了「同意」，若同意界面未充分揭示 核选项，仍是 治理设计失败。

铸造的铁律

铁律实践
最小权限生产只读默认；写操作单独角色
双人复核破坏性 API 必须第二人批准
动作白名单禁止 delete-env、drop database 等除非工单类型匹配
可回滚基础设施 as code + 自动备份
认知隔离Agent 的「建议」与「执行」账户分离

5.9 第 4 代：ClawHavoc（ClawHawk）供应链（2026-02）

安全界多称 ClawHavoc（Koi Security 命名）； ClawHawk 指同一事件。

背景

  • OpenClaw 爆火 → 官方技能市场 ClawHub 数千 Skill。
  • Skill = Agent 会读并执行的 Markdown + 脚本（非传统编译代码）→ 「Markdown 级攻击面」。

规模（2026-02 披露）

六、六条底层规律

1. 基座模型能力是终极天花板

上下文 4K→200 万+、推理与多模态成熟，才使 Computer Use、长工作流可行。
Agent 不是大模型之外的魔法，而是释放基座已积累但未释放的能量余量。

2. 工程化架构对「模型暴力」的系统性胜利

Agentic Workflow + GPT-3.5 可碾压裸跑 GPT-4。
演进链：Prompt Engineering → Context Engineering → Harness Engineering。

3. 开放协议重塑价值分配

  • MCP → 杀死大量工具联通中间层
  • Skills → 杀死大量专长封装套壳
  • AGENTS.md → 逐渐统一各 IDE 私有 rules

竞争焦点：经生产验证的垂直技能集 + 数据反馈 + 信任（假设 AGI 短期不出现）。

4. 人机信任边界逐代外推

世代人类愿意交给 AI 的事
第 0 代阅读生成文本
第 1 代调用预定义 API
第 2 代编排多步工作流
第 3 代操控屏幕/终端
第 4 代无监督 24 小时常驻

信任扩大 ↔ 风险半径同步扩大。

5. 灾难为下一代铸造铁律

详见 §五 泡沫与事故年鉴 各小节「铁律/教训」。摘要：

事故铁律
AutoGPT 无限循环结构化编排、终止条件、状态机
Vibe Coding 宿醉评估驱动开发、测交付不测打字
Kepler/Kiro最小权限、双人复核、禁止核选项
ClawHavocSkill 供应链审计、沙盒、记忆投毒防护

标准往往是事故逼出的，不是委员会投票。

6. 寒武纪大爆发 → 大灭绝

  1. 能力升级 → 补丁产业蒸发
  2. 交互范式代际替换 → 上一代降门槛工具变累赘
  3. 误把红利当护城河 → 半年后无竞争优势

七、真正的护城河

当能力被基础设施吞噬后，仍可能剩下：

  1. 垂直领域深度：真实流程、风险、异常、责任边界
  2. 数据飞轮：真实使用中的高质量反馈 → 迭代甚至领域微调
  3. 用户信任：是否愿意交付更高价值、更长周期、更高风险的任务

除此之外很多项目只是临时泡沫；能高位套现是本事，别把自己也骗了。

八、成熟 Agent 的定义

AI Agent 正从「人类意识的延伸工具」走向具备认知循环、持久身份、记忆与（未来）物理行动能力的自主实体。

真正成熟的 Agent：

  • 不是最敢自动执行的那个
  • 而是在合适边界内可靠完成任务
  • 知道何时验证、暂停、请人确认

进步 ≠ 仅模型变强，同时 = 信任扩大 + 风险扩大 + 治理难度扩大。
